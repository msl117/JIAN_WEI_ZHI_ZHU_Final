# 项目功能与代码说明

## 1. 项目概述

项目名称：基于安路 FPGA 的实时工件边缘检测系统。

系统以安路 PH1P35 为核心，通过 SC520CS MIPI 摄像头采集 720p 图像，在 FPGA 内完成传统图像处理和工件检测，不依赖 Linux、CPU 或神经网络模型。处理后的画面通过 DDR 帧缓存和 HDMI 输出，并在画面上叠加检测状态、统计数据和辅助信息。

系统定位为小型工位的脱机轮廓检测原型，适合深色工件、浅色背景、固定摄像头和相对稳定照明条件。它不是通用颜色识别器，也不是经过数据集训练的 AI 质检系统。

## 2. 完整数据流

```text
SC520CS
  -> MIPI D-PHY 双 lane
  -> CSI 解包
  -> RAW10 解包
  -> 去马赛克
  -> AWB
  -> RGB 处理分支
       |- 原始 RGB
       |- 官方参考 Sobel 边缘
       |- 灰度输出
       |- 固定 ROI 二值化
  -> 128 bit 图像打包
  -> DDR 四帧缓存
  -> video_out 读出
  -> HDMI mixer
       |- Logo
       |- 模式和增益文字
       |- 黑像素数、RESULT、SHAPE、SCORE、ANGLE
       |- 工件有效时的外接矩形框
       |- QUALITY、GRADE、PASS/FAIL 计数
  -> HDMI TX
```

检测支路从 ROI 二值图像旁路读取，不回压显示视频：

```text
ROI 二值流
  -> ROI 黑像素/边界特征
  -> 工件存在和面积 RESULT
  -> 4 x 4 采样、矩统计和主方向估计
  -> 旋转归一化 32 x 32 轮廓
  -> C7 学习模板 / 当前模板匹配
  -> SHAPE 结果
  -> ROI + SHAPE QUALITY
```

## 3. 显示模式和操作

| 按键 | 管脚 | 功能 |
| --- | --- | --- |
| `I_button[0]` | D5 | 摄像头增益/调光等级调节 |
| `I_button[1]` | A9 | 原图与 Sobel 边缘图切换 |
| `I_button[2]` | B9 | 灰度、ROI 二值化、DEBUG ROI 循环切换 |
| `I_button[3]` | C7 | 当前工件面积基准和形状模板学习/重新标定 |
| `I_sw_awb` | A4 / SW1 | 拨上启用 AWB，拨下旁路 AWB |
| `O_beep` | C12 | 低电平有效的稳定 NG 报警 |

五种显示模式为：

| 模式 | 图像 | 说明 |
| --- | --- | --- |
| MODE 0 | 原始 RGB | 摄像头原始彩色画面 |
| MODE 1 | Sobel EDGE | 硬件流水线边缘图 |
| MODE 2 | GRAYSCALE | 共享灰度结果 |
| MODE 3 | ROI BINARY | 固定区域阈值二值化 |
| MODE 4 | DEBUG ROI | ROI 二值图和检测框/状态信息 |

建议的标定流程：固定摄像头和照明，将完整合格工件放入 ROI，等待 `OBJECT` 稳定后短按 C7；等待模板准备完成，再观察 `SHAPE: MATCH`。复位或断电后模板需要重新学习。

AUTO 仅调模拟增益，曝光寄存器保持固定。DEBUG ROI 模式下工件在场时冻结 AUTO；其他模式允许根据画面两侧背景测光继续调节。SW1 改变 AWB 时，需等待新画面稳定，再按 C7 重新学习面积和形状基准。DEBUG ROI 左侧显示 `AWB: ON/OFF`；该文字表示开关状态，刚拨动时可能先于 DDR 中的旧画面更新。

## 4. ROI 和检测

当前固定参数：

```text
ROI_X_START = 160
ROI_X_END   = 1120
ROI_Y_START = 90
ROI_Y_END   = 630
BINARY_THRESHOLD = 128
```

ROI 内使用灰度和阈值产生黑/白图像，ROI 外为黑色。检测支路采用“深色工件、浅色背景”极性：ROI 内黑像素作为工件候选，统计黑像素数量和最小/最大 X/Y，生成外接矩形。

`I_tdata[95:72]`、`[71:48]`、`[47:24]`、`[23:0]` 对应连续像素 `x+3`、`x+2`、`x+1`、`x`。检测支路按 `x` 到 `x+3` 的顺序解释数据。

面积 RESULT 是独立于 SHAPE 的工件存在/面积范围判断。SHAPE 是旋转归一化后的轮廓模板匹配。两者分别显示，不能把 SHAPE NG 误解为面积 RESULT NG。

## 5. QUALITY

`quality_score_ctrl.v` 在控制时钟域内以串行定点除法计算：

- ROI 子分数由当前黑像素数与 C7 面积基准的相对误差得到。
- SHAPE 子分数同时考虑失配数和轮廓并集，避免将失配像素数直接当作相似度。
- 默认权重为 ROI 40%、SHAPE 60%。
- 结果进行饱和，不能超过 0 到 100。
- 未标定、无工件、形状模板未准备好、并集为零或帧数据不完整时显示 WAIT。
- 当前工程将满足原面积/形状条件的评分显示为 PASS，否则显示 FAIL；QUALITY 不会反向修改原有 RESULT 或 SHAPE 结论。

## 6. OSD 和报警

HDMI mixer 在视频帧边界锁存检测元数据，活动视频期间不主动改变当前帧显示状态。OSD 主要区域如下：

- 左上：Logo、模式文字、增益文字。
- 右上：BLACK 黑像素统计、QUALITY、GRADE、PASS/FAIL 计数。
- 检测信息：OBJECT/NO OBJECT、RESULT、SHAPE、SCORE、ANGLE。
- 工件存在状态有效时：在当前有效外接矩形位置绘制检测框；此条件未按显示模式限制。
- MODE 4：额外显示 SHAPE、SCORE、ANGLE 和 PASS/FAIL 计数。
- MODE 4：显示跟随包围框的 ID/中心坐标、SW1 的 AWB 状态，以及摄像头输入帧率 `C-FPS` 和 RAW10 输入至 HDMI 选帧的 `LAT`（不含显示器面板延迟）。

QUALITY 发布 FAIL 事件时，控制逻辑驱动 `O_beep` 约 500 ms。蜂鸣器低电平有效；复位时关闭。当前 RTL 不会因脉冲期间随后出现 OK/WAIT 而立即截断这次报警，所以不能宣称“OK/WAIT 一出现蜂鸣器立即关闭”。

## 7. 当前实现边界

1. 二值化阈值受照明、曝光、白平衡和背景颜色影响。
2. 当前方案不是颜色分类：红色物体如果二值化后的轮廓和黑色样品相近，可能被判为相近结果；颜色本身没有作为独立特征输入。
3. 形状模板为低分辨率归一化轮廓，适合轮廓级判断，不适合细小缺陷和纹理检测。
4. 圆形、多目标、严重遮挡或工件离开 ROI 时，主方向和模板匹配可靠性会下降。
5. 检测元数据在 HDMI 帧边界锁存，但面积/形状结果没有逐项与 DDR 图像帧槽绑定；快速移动时框和画面可能短暂不同步。
6. 当前文档中的 bitgen、仿真和资源报告不等价于开发板实测；板级结果必须按验证清单重新记录。
